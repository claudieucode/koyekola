## 3. Audit de l'éditeur Kolakisa
**Architecture** : `public/js/page-builder.js` (9 403 lignes, tout : historique 150 étapes, calques, inspecteur, rendu, copier-coller, palette Ctrl+K, enregistrement avec contrôle de révision) + 11 modules satellites ; `src/marketing/pages/nodes.js` (grammaire fermée : 162 types, 110 propriétés de style, 4 écrans, 5 états) ; `parts.js` ; rendu unique côté serveur (iframe + `POST /pages/:id/rendu`).
**Theme Builder** : pas d'éditeur propre, il ouvre le même éditeur (`?modele=`). Bon point.
**Duplications constatées** : (1) deux gestionnaires de modèles (nouveau `src/themeBuilder/*`, ancien `pages/themeTemplates.js` + `appearanceEditor.js`) avec deux moteurs de score/conditions ; (2) deux systèmes de révisions (`themeBuilder/revisions.js` et `services/revisions` + `web/history.js`) ; (3) seuils d'écran écrits deux fois (`nodes.js:2013`, `siteSettings.js:9`) plus des valeurs de repli côté client.
**Vérification de la matrice** (lecture du code, rien exécuté) : 52 lignes « Complet » échantillonnées sur toutes les familles → fonction retrouvée dans le code pour 52/52 ; preuve citée périmée (numéros de ligne) pour 8/52 ; aucune ligne « Complet » trouvée purement visuelle ou défectueuse. En sens inverse, des « Absent » périmés (couleurs personnalisées EL-SS002/003 existent ; Lottie et Playlist vidéo existent). Réserve : ceci prouve la présence du code, pas le fonctionnement de bout en bout.
**Points ouverts** : tremblements/déplacements du canvas : aucun document ni règle de stabilisation, état **à investiguer en navigateur** ; écrans supplémentaires (laptop, paysage) absents (EL-SS029) ; breakpoints : 3 seuils réglables seulement ; indicateurs du navigateur d'éléments partiels (UI023) ; grille avancée (auto-fit, zones nommées) non vérifiée ; fichier unique de 9 400 lignes modifié par plusieurs sessions (risque de fusion).

## 5. Constat principal
Les fonctions de l'éditeur sont en grande partie présentes. L'écart avec « parité Elementor » est donc moins dans l'absence de fonctions que dans (a) la **preuve de fonctionnement de bout en bout** (aucune ligne n'est classée « opérationnelle » par exécution dans cette phase), (b) la **stabilité du canvas** (non mesurée), (c) les **duplications** de moteurs, (d) quelques fonctions réellement absentes ou limitées (écrans supplémentaires, grille avancée, carte de widgets WooCommerce complète, popups avancées, version V4 atomique).
